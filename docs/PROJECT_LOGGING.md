# Protocolo de bitácora GitHub ↔ Notion

Cahíta Histórico Digital mantiene dos fuentes de verdad complementarias:

- **GitHub**: fuente de verdad técnica para archivos, datos, schemas, transcripciones, documentación, commits, Issues, releases y QA.
- **Notion**: fuente de verdad estratégica y de estado para hitos, decisiones metodológicas, hallazgos, incidencias, cobertura, productos derivados y siguiente acción.

## Regla de registro

Cada bloque sustantivo de trabajo debe producir, como mínimo:

1. evidencia técnica versionada en GitHub;
2. actualización de cobertura cuando cambie el estado cuantitativo;
3. registro cronológico en la base de Notion `Bitácora de ejecución — Cahíta Histórico Digital`;
4. actualización de Issues cuando cambie una fase o aparezca una incidencia metodológica relevante.

Los microcambios mecánicos pueden agruparse en un lote. No deben agruparse ni omitirse decisiones editoriales, cambios de frontera textual, nuevas categorías de datos, discrepancias OCR/facsímil, cambios de autoridad de una lectura ni hitos de publicación.

## Autoridad

La existencia de un registro en Notion no cambia el estado filológico de los datos. `human_verified` sólo puede utilizarse cuando exista cotejo humano identificable contra el facsímil. Notion documenta el proceso; GitHub conserva la evidencia técnica reproducible.
